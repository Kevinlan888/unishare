# UniShare Android 客户端设计

日期：2026-10-07

## 1. 背景与产品定义

UniShare 是以设备为会话对象的局域网分享工具，而不是即时通讯软件。Android 客户端面向需要在自己的可信设备或同一局域网内的临时设备之间传递内容的用户，通过现有 `share-sdk` 完成发现、配对、连接与传输。

仓库目前已有支持 API 26+ 的 Kotlin SDK、JNI 适配层及跨平台验收，但没有 Android 应用模块。首版 Android 客户端必须接入真实 SDK，提供可实际使用的端到端收发能力；界面参考已批准的移动端设计图，并与 Windows 客户端保持相同的产品语义和安全策略。

## 2. 目标

- 使用现有 `ShareSdk` 完成设备发现、配对、文本、图片和文件的真实收发。
- 以设备而不是联系人组织分享行为，并用活动流表达传输过程。
- 默认只在应用前台发现和接收；用户可显式开启后台接收。
- 用户主动发起的传输在应用退到后台后仍可安全完成。
- 清晰展示等待、传输中、完成、拒绝、取消和失败状态。
- 提供简体中文和英文，并跟随系统语言与浅色/深色主题。
- 遵守 Android 存储、通知、前台服务和局域网权限模型。
- 持久化近期活动摘要、普通文本正文和小型图片预览；剪贴板来源内容、文件内容和发送源 URI 不持久化。

## 3. 非目标

首版不提供：

- 联系人、群聊、消息已读、输入状态或任何云端账户能力；
- 互联网中继、云同步或跨网络发现；
- 文件夹打包或文件夹传输；
- 链接预览卡片，链接仅作为普通文本发送；
- 自动剪贴板同步或后台读取剪贴板；
- 自动接受图片或文件；
- 平板专用双栏或折叠屏专用布局；
- 失败传输的自动重试。

## 4. 技术方案

### 4.1 技术栈与模块

在现有 Android Gradle 工程中新增独立 `app` 模块，采用 Kotlin、Jetpack Compose、Material 3、Navigation Compose、ViewModel、Kotlin Flow、Room 和 DataStore。应用直接依赖仓库内的 `:share-sdk` 模块，不复制 SDK 逻辑，也不修改其公开接口。

应用最低支持版本与 SDK 一致，为 Android 8/API 26。首版使用仓库当前已验证的 `compileSdk 36` 与 `targetSdk 36`；Android 17/API 37 设备沿用目标 36 应用的兼容权限路径。未来提升目标 SDK 时，必须先加入对应的局域网运行时权限流程，且不得改变本文定义的用户行为。

应用使用 `com.unishare.app` 作为 namespace 与 application ID，并按职责拆分为以下顶层包：

- `presentation`：Compose 页面、组件、导航、UI 模型与 ViewModel；
- `domain`：设备、配对、会话、传输、接收策略、活动状态和用例；
- `data`：SDK 适配器、仓储、Room、DataStore、暂存文件与内容发布；
- `service`：后台接收和活动传输使用的 Android 前台服务；
- `platform`：通知、权限、内容选择器、剪贴板和系统目录等 Android 集成。

页面不直接访问 `ShareSdk`、Room、DataStore、`ContentResolver` 或 Android Service。领域接口隔离平台能力，使 ViewModel 与状态机可使用假实现进行测试。

### 4.2 SDK 会话所有权

进程内只创建一个 `ShareSdk` 实例，由应用级 `ShareSessionManager` 负责初始化、监听、启动、停止和关闭。Activity、ViewModel 和前台服务不各自创建 SDK。

`ShareSessionManager` 将 SDK 回调转换为有序的 Flow 和不可变快照。它维护订阅所有权并确保：

- 初始化成功后才执行服务命令；
- 同一 SDK 事件只进入应用状态机一次；
- 前后台切换不会重复注册监听或重复创建设备；
- `stop`、`close` 和进程退出遵循 SDK 的操作完成与回调排空约束；
- UI 更新只在主线程发生，SDK 回调线程不直接访问 Compose 状态。

### 4.3 前后台生命周期

“后台接收”设置默认关闭。

- 关闭时：应用可见期间设置 SDK 为前台并启动发现与接收；没有活动传输且应用退到后台后停止 SDK。
- 开启时：前台服务显示持续通知，并在应用退到后台或锁屏后维持 SDK 运行、设备发现和接收。
- 活动传输：无论后台接收设置为何，只要用户已开始发送或已接受接收，应用就临时维持前台服务直至所有活动传输进入终态。
- 关闭设置：若当前无传输则立即停止常驻接收；若有传输则显示“正在停止”，在任务完成后停止。
- 进程恢复：数据库中的非终态活动统一标记为失败或已中断，并清理无法关联到当前 SDK 会话的暂存文件。

前台服务只承担 SDK 生命周期与通知，不持有 Compose 导航或页面对象。

## 5. 数据与状态模型

### 5.1 设备模型

设备仓储合并 `discovery.devices()`、发现事件和 `connections.trustedDevices()`，产生稳定的设备列表：

- 本机设备；
- 可信在线设备；
- 可信离线设备；
- 附近但尚未配对的设备。

设备 ID 是列表去重与导航的稳定主键。发现更新修改已有记录，离线事件保留可信设备并更新在线状态。身份变化立即阻止该设备上的新传输，直到用户忘记设备并重新配对。

### 5.2 活动模型

每条活动包含活动 ID、设备 ID、传输 ID、方向、内容类型、展示名称、MIME、声明大小、已传输大小、状态、时间、错误分类，以及成功接收内容的最终 URI。状态为：

- 等待对方；
- 传输中；
- 已完成；
- 已拒绝；
- 已取消；
- 失败。

前两者为非终态，其余为终态。发送操作结果、`TransferEvent.Progress` 和 `TransferEvent.Result` 按传输 ID 归并到同一活动；重复结果和终态后的进度必须忽略。手动重试创建新的活动与传输，并关联原失败活动。

Room 每台设备最多保留 500 条且不超过 30 天的活动及其关联预览。清理在启动后和写入终态后异步执行。普通文本正文保存在应用私有数据库的独立预览表中；图片只保存最长边不超过 512 像素且不超过 256 KiB 的缩略图。剪贴板来源内容、图片原图、文件内容和发送源 URI 不持久化。最终 URI 仅用于打开用户已成功接收的正式内容，不写入诊断日志。应用关闭 Android 云备份。

### 5.3 设置模型

DataStore 保存：

- 本机设备名称；
- 接收目录授权与展示名称；
- 后台接收开关，默认关闭；
- 通知开关；
- 语言策略，默认跟随系统；
- 主题策略，默认跟随系统。

默认接收位置为系统下载集合中的 `UniShare`。用户通过系统目录选择器更改位置，应用保存持久 URI 权限；授权失效时停止发布新内容并引导重新选择目录，不静默改存其他位置。

## 6. 信息架构与页面

应用采用单 Activity 与 Navigation Compose。手机底部导航固定为“分享、设备、历史、设置”。首版以手机竖屏为主，横屏与大屏保持内容可滚动、操作可达，但列表与详情仍使用顺序导航。

### 6.1 分享首页

分享首页包含：

- 本机设备卡，展示设备名称与运行状态；
- 最近活动，展示设备、最后一项摘要、时间和进度；
- 附近设备，区分可信、未配对、在线和离线状态；
- 刷新动作与悬浮分享按钮。

选择设备进入设备会话。悬浮分享按钮先要求用户选择目标设备，再进入内容选择流程。

### 6.2 设备会话

顶部展示返回、平台图标、名称、在线/信任状态和更多操作。主体按日期排列活动：发出靠右并使用强调色，接收靠左并使用中性色。文本、图片和文件使用独立卡片；传输中显示进度、速率与取消，失败显示原因与手动重试。

底部提供文本输入、附件入口和发送按钮。附件底部面板只包含照片、文件、剪贴板、文本和链接。链接按文本发送；不展示文件夹入口。剪贴板仅在用户点击且应用可见时读取，支持文本和图片。

### 6.3 接收确认

图片和文件请求进入独立接收详情页，展示预览占位、名称、类型、大小、来源设备以及“拒绝”和“接受”。首版不提供“始终接受此设备文件”，以保证图片和文件始终逐次确认。

可信设备的文本自动接受到私有暂存文件，成功后在当前会话展示正文，并随活动保留规则保存在本机；未配对或临时设备的文本、图片和文件均必须确认。接收规则由领域策略决定，页面不能绕过。

### 6.4 配对

首次连接时显示双方应核对的完整六位安全码，并提供“匹配”和“不匹配”。前导零不可省略。双方确认成功后设备进入可信列表；拒绝、超时、认证失败或身份变化均不建立或恢复信任。

### 6.5 设备、历史与设置

- 设备页：分别展示可信设备、附近设备和离线设备，支持连接、查看详情和忘记设备。
- 历史页：支持搜索，并按设备、方向、类型和状态筛选活动摘要。
- 设置页：提供设备名称、接收目录、后台接收、通知、语言、主题、存储说明和关于信息。

## 7. 发送与接收流程

### 7.1 发送

- 照片使用系统 Photo Picker；文件使用系统文件选择器，不申请整盘存储权限。
- 应用在发送前读取内容名称、MIME 和精确字节数；无法确定精确大小时不提交 SDK，并提示用户重新选择受支持来源。
- 提交后立即创建等待活动，操作结果返回传输 ID 后更新同一记录。
- 文本通过 `sendText`，图片通过 `sendImage`，其他文件通过 `sendFile`。
- 发送源只在当前操作期间持有；应用不得删除或修改用户源内容。

### 7.2 接收暂存与发布

接受请求前，应用在私有缓存中创建可删除的普通暂存文件，并通过应用自有 `ContentProvider` 提供 `content://` URI。Provider 必须支持随机系统文件描述符访问和 `delete`，满足 SDK 对失败、拒绝和取消时删除暂存目的地的契约。

收到成功终态后：

- 文本：从暂存文件按 UTF-8 读取，保存正文到独立的本机预览记录并删除暂存文件；
- 图片或文件：复制或移动到系统下载集合的 `UniShare`，或用户授权的目录；发布成功后删除暂存文件并记录最终 URI；
- 重名：使用 `名称 (1).扩展名` 递增，不能覆盖现有内容。

若发布失败，活动显示存储失败，暂存内容不作为正式文件暴露。应用允许用户在当前进程内修复目录后再次发布，暂存文件最多保留 10 分钟；用户放弃、期限到达或应用下次启动时必须清理。诊断日志不得记录完整 URI、路径或内容。

### 7.3 接收策略

- 可信设备：文本自动接受；图片和文件逐次确认。
- 未配对或临时设备：所有内容逐次确认。
- 接收请求在应用可见时显示对应页面，在后台接收开启时通过通知引导用户打开确认。
- 通知本身不自动创建正式文件，也不提供绕过应用确认策略的直接接受动作。

## 8. 权限与系统集成

应用仅在功能首次需要时请求权限：

- 通知权限用于前台服务和后台请求提醒；拒绝后后台接收开关保持关闭并显示设置入口。
- 局域网权限按设备系统版本与应用目标 SDK 的要求请求；拒绝后保留离线界面和重试入口。
- 目录访问通过系统选择器和持久 URI 授权完成，不请求广泛文件权限。

后台接收开启时持续通知显示当前状态、在线设备数量和“停止后台接收”动作。活动传输通知显示进度与取消动作。通知点击进入对应设备会话或接收确认页。

## 9. 错误处理

- 权限拒绝：说明缺少的能力并提供重试或系统设置入口。
- 发现失败：分享页显示非阻塞横幅，历史和设置仍可使用。
- 网络中断、超时或设备离线：活动进入失败，允许手动重试，不自动重发。
- 身份变化：立即阻止传输，提示忘记设备后重新配对。
- 目录不可写或授权失效：不接受新的文件/图片请求，保留尚未超时的请求并引导修复。
- 失败、拒绝、取消或完整性错误：删除暂存文件，不发布半成品。
- 剪贴板无受支持内容：不创建活动，只显示可理解提示。
- SDK 初始化或服务启动失败：保持停止状态，清理订阅并允许显式重试。

错误提示使用稳定的用户分类；平台错误码只进入不含敏感信息的诊断数据。任何失败都不得记录正文、剪贴板内容、完整路径、完整 URI 或密钥材料。

## 10. 视觉、本地化与辅助功能

界面采用 Material 3 组件和自定义设计 token。参考图定义的视觉方向为：低对比度蓝灰背景、白色或表面色卡片、蓝色主操作、较大圆角、轻量阴影和清晰的状态层级。深色主题保持相同信息层次，不硬编码浅色值。

所有可见字符串进入简体中文和英文资源，并按系统区域格式化日期、时间、文件大小和传输速率。语言和主题默认跟随系统。

所有触控目标至少 48dp；状态不能只依赖颜色；图标按钮必须有语义标签；焦点顺序与视觉顺序一致；配对码完整朗读；动态进度避免高频播报，仅在关键阶段和终态更新。系统字体放大、横屏以及小屏设备不能裁切接受、拒绝、取消和发送等关键操作。

## 11. 测试策略

### 11.1 单元测试

- 发现、更新、离线、信任与设备去重；
- 可信与临时设备的接收策略；
- 活动状态转换、终态不可逆与重复事件幂等；
- 操作结果与传输 ID 的关联；
- 重试创建新活动并关联旧记录；
- 每设备 500 条与 30 天的历史清理；
- SDK 错误到用户错误的映射。

### 11.2 数据与生命周期测试

- Room 迁移、查询和清理；
- DataStore 默认值与设置恢复；
- ContentProvider 的普通文件、删除与 URI 边界；
- 成功发布、重名、拒绝、取消、失败和崩溃恢复时的暂存清理；
- Activity 前后台、后台接收开关、活动传输临时服务与受控停止；
- 进程恢复后非终态活动和孤立暂存文件的处理。

### 11.3 Compose 与可访问性测试

- 分享、会话、接收、配对、设备、历史和设置页面；
- 加载、空状态、权限拒绝、离线与 SDK 异常状态；
- 浅色、深色、简体中文、英文和大字体；
- 关键语义、触控目标、焦点顺序与导航恢复；
- 代表性手机竖屏、横屏和大屏可用性。

### 11.4 真实集成验收

至少使用一台真实 Android 设备和 Windows 客户端验证：

- 发现、离线、重新发现和首次配对；
- 信任在应用重启后保持，忘记设备后需重新配对；
- 文本、图片、文件以及显式剪贴板发送；
- 接受、拒绝、取消、超时、断网和文件完整性；
- 后台接收关闭与开启两种行为；
- 活动传输退到后台后完成，结束后临时服务停止；
- 接收目录、重名、授权失效和暂存清理；
- 中英文、浅色/深色和系统字体放大。

## 12. 完成标准

Android 首版满足以下条件时视为完成：

- API 26+ 可安装并通过真实 SDK 初始化；
- 可发现、配对和管理可信设备；
- 可真实发送和接收文本、图片和文件；
- 可信文本自动接收，图片和文件逐次确认，临时设备全部确认；
- 后台接收开关默认关闭且行为符合本文定义；
- 活动状态、进度、取消、重试和错误与 SDK 终态一致；
- 成功前不发布文件，所有失败路径均清理半成品；
- 历史保留期内可恢复普通文本正文和图片缩略图，不保存剪贴板来源内容、图片原图或文件内容；
- 简体中文、英文、浅色、深色和核心辅助功能通过；
- 单元、数据、生命周期、Compose 和真实 Android↔Windows 验收通过。
