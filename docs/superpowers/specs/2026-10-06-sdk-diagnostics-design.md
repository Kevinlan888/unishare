# SDK 全链路诊断日志设计

日期：2026-10-06
状态：待书面规格审阅

## 意图和范围

用户希望先增加日志，用于定位目前文字和文件发送均失败、文件发送时界面可能卡住、接收方不能接受的问题。本次只增加诊断能力，不猜测或修改发送协议、传输状态机和 UI 行为。日志要覆盖初始化、启动、发现、连接、配对、发送、接收、取消、终态及其失败；同时覆盖文件提交与接收目的地准备这两个原生 SDK 之外的边界。

成功标准：两台 Windows 机器各自的 `diagnostics.log` 能从一次用户操作辨认最后完成的阶段、下一阶段是否开始、错误分类与平台错误码；记录不含文件路径或名称、设备标识或名称、地址、配对码、传输正文、密钥、自由格式异常消息。正常运行时不能因逐块记录造成日志暴涨，也不能因日志失败改变操作结果。

## 方案选择

选择独立、可选的结构化诊断回调：C++ SDK 产生固定枚举事件，经 C ABI 交给 Windows .NET 适配层，再通过已有 NLog 文件目标写入。C++ 核心不依赖 NLog，也不自行决定磁盘位置。现有 `usdk_event_handler` 是业务事件，含敏感字段，且只在 `Start` 时注册，不复用它；C++ 直接写文件会重复实现路径、轮换及隐私策略，并让跨平台 SDK 管理宿主存储。

## 事件模型和阶段

诊断记录只含固定宽度字段：`component`、`stage`、`outcome`、SDK 错误分类、可选平台错误码，以及单进程内的短暂关联序号。SDK 为每次连接/传输尝试分配本地序号，相关阶段沿用它；Windows 宿主在提交边界把本地活动与原生操作对应起来。序号不持久化，也不使用设备或传输 ID。双端日志靠操作时间、方向和内容类型比对，不宣称可自动关联两台机器的记录。阶段和结果采用显式数值枚举；未知枚举在 .NET 映射成 `Unknown`，不得直接格式化任意原生内存。`Began`、`Succeeded`、`Failed`、`Cancelled` 为结果；`Cancelled` 与 `Failed` 分开。

覆盖范围分层：

1. 生命周期与发现：初始化边界、权限、监听、发布、浏览、网络变更和停止。
2. 连接与配对：连接请求、socket 建立、TLS/身份验证、配对请求及决定、连接就绪或断开。
3. 传输：提交、查找已认证连接、发出/收到 Offer、接受/拒绝、数据流开始、完成校验、对端确认、取消和终态。发送与接收分别标记；文本、图片、文件以固定内容类型枚举区分。
4. Windows 宿主边界：本地文件打开/注册、接收目标准备、原生命令提交及回调完成。这样可以区分 UI 卡在进入 SDK 之前，还是 SDK 内部。

只在阶段转换、失败和终态发事件；不记录每个数据块、字节数、进度百分比或每个发现的设备。重复的网络浏览错误按阶段及错误类别限频，丢弃的低优先级日志用固定计数事件报告。

## 接口与生命周期

共享核心提供每 SDK 实例的可选 `DiagnosticSink`/回调，不把日志文本或 NLog 类型放进核心接口。C ABI 增加 `usdk_set_diagnostic_handler(sdk, handler, context)` 和定长 `usdk_diagnostic_event`。这是向现有 ABI v1 增加导出符号，不改 `usdk_config` 或已有结构布局；新 Windows 包必须搭配含新符号的 DLL。注册发生在 `usdk_create` 成功后、`usdk_start` 前，因此创建/加载失败仍由现有 .NET 初始化日志记录。`DllNotFoundException` 发生在 DLL 加载前，原生日志无法记录它；本设计不替代 VC 运行库打包。

替换或注销回调沿用现有 C ABI 事件回调的失效和在途等待语义，销毁后不得回调托管侧。C++ 不在内部互斥锁下调用宿主代码，异常不得跨 C ABI。Windows .NET 回调只复制固定字段到有界队列，后台消费者写 NLog；队列满时丢弃诊断事件而不阻塞网络/传输线程，并记录丢弃计数。停机时先注销原生回调，再释放托管回调根，最后有限时间刷新队列。NLog 文件继续使用现有大小与数量限制。

## 错误处理和隐私

错误只输出 `ShareError.code` 与 `platform_error`；禁止输出 `ShareError.message`、异常消息/堆栈、OpenSSL 错误文本、源/目标路径、文件名、MIME 自由文本、设备信息或帧内容。日志调用必须是 best-effort：回调抛错、队列满、文件不可写均不能改变 SDK 返回值或业务事件顺序。若阶段尚未到达，则没有该阶段的 `Began`；若失败发生，须有最后一个阶段的 `Failed` 与原始错误分类，而不是仅在顶层给一个笼统的发送失败。

## 验证

- C++ 单元测试覆盖各阶段成功与注入失败：权限、监听、发布、连接、配对、Offer、接受/拒绝、流读写、校验、取消；检查终态只记录一次且错误码保留。
- C ABI 测试覆盖结构布局、导出符号、注册/替换/注销、销毁与在途回调竞态。
- .NET 测试用假原生 API 验证枚举映射、队列背压、回调生命周期以及发送/接收宿主边界；NLog 测试验证轮换、错误级别和敏感数据不落盘。
- 集成验证在两台机器分别发送文本与文件，比较双端阶段序列，确认失败位置；不把“日志已加入”当作发送问题已修复。

## 非目标

本次不修改发送/接收行为，不做自动上传、遥测、用户身份关联、逐包网络跟踪，也不解决尚未打包的原生依赖问题。
