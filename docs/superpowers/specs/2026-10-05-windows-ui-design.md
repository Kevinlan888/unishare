# UniShare Windows 原生应用 UI 设计

日期：2026-10-05

## 1. 背景与产品定义

UniShare 不是传统即时通讯软件。它是一个以设备为会话对象的跨平台分享工具：用户选择一台设备，然后向该设备投递文本、图片、文件或当前剪贴板内容。界面可以采用类似会话流的表达方式，但不提供联系人、群聊、社交关系、在线聊天或消息系统。

Windows 是第一个应用端，使用 Windows 原生技术快速交付。主要场景是用户在自己的多台可信设备之间随手互传，同时允许与同一局域网中的临时设备进行一次性分享。

现有跨平台 SDK 已提供设备发现、身份与信任、配对、连接、文本/图片/文件传输、进度、取消、接收确认和显式剪贴板访问。Windows 应用在这些能力之上提供产品界面、生命周期、本地活动摘要、文件落盘、通知和系统托盘。

## 2. 目标

- 以设备而不是联系人组织全部分享行为。
- 用户打开应用后最多两次操作即可向可信设备发送内容。
- 关闭主窗口后继续驻留系统托盘，保持发现与接收能力。
- 每次传输都明确展示方向、类型、状态、进度和失败原因。
- Windows 端保持原生外观、键盘行为、通知、主题和辅助功能。
- 只保存近期活动摘要，不创建用于历史展示的内容副本。
- 首版同时支持简体中文和英文，并跟随 Windows 浅色或深色主题。

## 3. 非目标

首版不提供以下能力：

- 联系人、群组、聊天室、已读回执、输入状态或社交资料；
- 云端账户、互联网中继、云同步或跨网络发现；
- 文件夹打包发送；
- 链接卡片预览；
- 表情面板；
- SDK 尚未支持的内容类型；
- 独立 Windows 服务或前后台进程间通信；
- 自动重发失败内容。

## 4. 技术方案

### 4.1 技术栈

应用采用 WinUI 3、C# 和 Windows App SDK。它通过现有 `unishare.dll` 的稳定 C ABI 与原生 SDK 集成，不在 UI 项目中直接链接或暴露 C++ 对象。

应用使用单个用户进程。主窗口、系统托盘、Windows 通知、原生 SDK 会话和本地状态存储都在该进程中。关闭主窗口只隐藏窗口；只有托盘菜单中的“退出”才停止 SDK 并终止进程。

首版采用 MSIX 打包。开机启动作为设置项提供，默认关闭；启用后仍以当前用户身份运行，不使用系统服务。

### 4.2 项目边界

- `UniShare.App`：WinUI 页面、窗口、主题资源、系统托盘、通知、导航和应用生命周期。
- `UniShare.Native`：P/Invoke 声明、原生类型转换、句柄所有权、回调生命周期、异步任务封装和 SDK 事件流。
- `UniShare.Application`：`ShareSession`、设备聚合、传输编排、接收策略、活动状态机和 ViewModel。
- `UniShare.Infrastructure`：SQLite 活动摘要、设置、接收目录、临时文件发布和诊断日志。
- 测试项目：分别覆盖原生桥接、应用状态、存储、ViewModel 和真实 DLL 集成。

这些边界通过 C# 接口通信。页面不直接调用 P/Invoke、SQLite 或文件系统。

### 4.3 原生桥接约束

- 每个 `usdk_span` 和事件中的嵌套内存在原生回调返回前复制为托管值。
- SDK、平台和流句柄使用专用安全句柄封装，并按照 SDK 契约释放。
- 原生回调委托在 SDK 完全停止前保持强引用。
- 一次性完成回调转换为异步任务；延续任务异步执行，避免在原生回调栈中重入。
- 重复或迟到的终态事件不会第二次完成同一操作。
- 所有面向 UI 的状态变化通过 WinUI 调度器发布；网络或文件回调不直接访问 XAML 对象。
- 应用退出顺序为：停止接受新操作、请求 SDK 停止、等待完成回调入队、释放 SDK、安全句柄和托盘资源、结束进程。

## 5. 应用组件

### 5.1 `ShareSession`

`ShareSession` 是应用级唯一会话，负责 SDK 初始化、启动、停止和恢复，并暴露设备、配对、传输、剪贴板及运行状态。窗口隐藏或重建不会创建第二个 SDK 实例。

### 5.2 `DeviceStore`

`DeviceStore` 合并发现中的设备、可信设备和连接事件，生成稳定的设备视图：

- 可信在线设备；
- 可信离线设备；
- 附近但未配对的设备；
- 当前选择设备。

同一设备的发现更新只更新现有条目，不在列表中产生重复项。可信设备优先于附近设备显示。

### 5.3 `ActivityStore`

`ActivityStore` 使用 SQLite 保存近期传输摘要。每条记录包含：

- 活动 ID、设备 ID、传输 ID和关联的重试来源；
- 收发方向与内容类型；
- 展示名称、MIME 类型和字节数；
- 创建、更新和完成时间；
- 当前状态、已传输字节数和面向用户的错误分类；
- 成功接收文件的最终本地路径。

数据库不保存文本正文、剪贴板正文、图片字节、文件内容或文件内容副本。当前进程可以在内存中显示刚发送或接收的文本；重启后对应历史项只显示“文本”及摘要。剪贴板内容从不写入数据库或诊断日志。

成功接收的文件是用户明确保存的正式文件，不属于历史副本。活动记录可以保存其路径以支持“打开文件”和“打开位置”；如果文件被移动或删除，这些操作变为不可用，但摘要仍保留。

默认保留每台设备最近 500 条且不超过 30 天的摘要。清理在应用启动后和新增终态记录后异步执行，不阻塞 UI。

### 5.4 `SettingsStore`

设置包括本机设备名称、默认接收目录、开机启动、通知开关、语言策略、主题策略和窗口状态。默认接收目录为当前用户的“下载/UniShare”，用户可以更改。

### 5.5 托盘与通知

系统托盘菜单提供：

- 打开 UniShare；
- 暂停接收或恢复接收；
- 退出。

托盘图标反映正常、正在暂停、已暂停和 SDK 异常状态。通知用于后台接收请求、自动接收结果和传输完成或失败。点击通知打开相应设备会话。

## 6. 主窗口信息架构

主窗口遵循已批准参考图的三栏结构和明亮、通透的 Windows 原生视觉语言。分享气泡代表设备间传输，不代表人与人聊天。

### 6.1 左栏

左栏包含一级导航：

- 分享：默认页面，显示设备会话；
- 设备：集中管理可信设备、附近设备和忘记设备；
- 历史：跨设备搜索和筛选近期活动摘要；
- 设置：设备名称、接收目录、启动、通知、主题和语言。

导航下方依次显示“可信设备”和“附近设备”。每个设备项显示平台图标、名称、在线状态和最新活动摘要。当前设备使用强调色背景和左侧选中指示条。

### 6.2 中栏

顶部显示当前设备名称、平台、在线与信任状态、搜索和更多操作。

主体按日期显示活动流：

- 发出内容靠右，使用强调色气泡；
- 收到内容靠左，使用中性色气泡；
- 图片、文件、文本和剪贴板使用各自卡片；
- 传输中卡片展示进度、速率、预计剩余时间和取消；
- 接收请求卡片展示接受与拒绝；
- 终态卡片展示完成、拒绝、取消或失败原因。

底部是快速分享栏。输入框仅用于向当前设备发送文本，提示语明确为“输入要发送到这台设备的文本，或拖入文件”。左侧加号菜单只包含图片、文件和剪贴板；不显示文件夹或表情。拖入单个文件或图片等价于相应发送操作。

### 6.3 右栏

右栏显示设备图像、名称、在线状态、文件/图片/文本/剪贴板快捷操作、平台、信任状态、最后在线时间和近期文件摘要。

“近期文件”来自活动数据库，不维护额外文件副本。成功接收且文件仍存在时可打开；其他条目仅展示摘要。

### 6.4 自适应布局

主窗口建议最小尺寸为 960×640。空间不足时先收起右侧详情栏，再将左侧导航压缩为图标栏；中间活动流始终保留。详情可从设备标题区域打开为侧边面板。

## 7. 核心交互

### 7.1 首次配对

1. 用户在“附近设备”中选择未配对设备。
2. 用户点击“连接并配对”。
3. 应用显示双方应核对的安全码，以及“匹配”和“不匹配”。
4. 用户确认匹配后，设备进入可信设备列表并打开对应会话。
5. 不匹配、拒绝、超时或认证失败时不建立信任，并显示可理解的结果。

设备身份变化属于高优先级安全事件。应用立即阻止继续传输，要求用户忘记设备后重新配对，不提供绕过按钮。

### 7.2 发送

发送文本、图片、文件或剪贴板后立即创建等待卡片。获得传输 ID 和进度事件后更新同一张卡片，不创建重复记录。发送回调和终态事件指向同一个状态机。

失败后用户可以重试。重试创建新的操作、传输 ID 和活动记录，并关联原失败记录。应用不自动重发，以免产生重复投递。

### 7.3 接收策略

可信设备：

- 文本自动接受到内存并进入活动流；
- 剪贴板内容自动接受并写入系统剪贴板；
- 图片和文件显示接受/拒绝请求。

临时设备：

- 文本、剪贴板、图片和文件全部需要接受或拒绝。

窗口可见时，请求显示在对应设备活动流中。窗口隐藏时，图片或文件请求通过 Windows 通知提示。通知提供“拒绝”和“查看并接收”：拒绝可以直接完成请求；“查看并接收”打开对应设备会话，通知本身不创建目标文件。

### 7.4 文件保存

接受图片或文件后，应用使用设置中的默认接收目录，不弹出“另存为”。应用在同一目标目录创建隐藏临时文件，交给 SDK 作为接收目标。完整性验证成功后才将其发布为最终文件。重名采用 `名称 (1).扩展名` 形式递增。

失败、拒绝或取消时清理临时文件。若目标目录不可写，应用保留接收请求并引导用户修复设置，不静默保存到其他位置。

### 7.5 窗口与后台生命周期

- 点击窗口关闭按钮：隐藏窗口并继续运行。
- 双击托盘图标或选择“打开 UniShare”：恢复并激活已有主窗口。
- 选择“暂停接收”：应用立即禁止新的发送并拒绝新收到的请求。若没有活动传输则调用 SDK `Stop`；若存在活动传输则进入“正在暂停”，等待它们到达终态后再停止 SDK。该操作不清除信任或历史。
- 选择“恢复接收”：调用 SDK `Start`，恢复发现、发布和接收；启动失败时保持暂停状态并显示错误。
- 选择“退出”：执行受控 SDK 停止和进程退出。

## 8. 活动状态与错误处理

活动状态为：等待对方、传输中、已完成、已拒绝、已取消、失败。前两者是非终态，其余是终态。终态后到达的进度或重复结果必须忽略。

错误处理规则：

- 网络中断、超时或设备离线：显示原因和“重试”，不自动重发。
- 身份变化：阻止传输并要求忘记后重新配对。
- 默认目录不可写：保留请求并打开目录设置入口。
- 文本自动接收失败：保留失败摘要并允许复制错误说明。
- 剪贴板写入失败：不覆盖现有剪贴板，并通知用户未能更新。
- 发现异常：页面顶部显示非阻塞横幅与重试操作，历史仍可查看。
- SDK 后台失效：托盘图标进入警告状态并发送通知。

SDK 错误码统一映射为稳定的用户说明。平台错误码和内部上下文只进入诊断日志。诊断日志不得包含文本正文、剪贴板正文或完整文件路径。

## 9. 主题、本地化与辅助功能

- 默认跟随 Windows 浅色或深色主题；应用不在页面中硬编码颜色。
- 颜色、阴影、圆角和状态色通过集中资源定义，并提供高对比度覆盖。
- 所有可见字符串使用资源文件，首版提供简体中文和英文，根据系统语言自动选择。
- 所有功能支持键盘操作，焦点顺序与视觉顺序一致，焦点样式清晰可见。
- 图标按钮、设备状态、接收请求和错误操作提供屏幕阅读器名称。
- 传输进度采用不会过度打扰的自动化播报，并在终态时明确播报结果。
- 界面在 100%、125%、150%、175% 和 200% 缩放下不得截断关键操作。

## 10. 测试策略

### 10.1 原生桥接测试

- C ABI 版本、结构体布局和枚举映射；
- UTF-8 与跨度数据在回调返回前完成复制；
- 安全句柄和回调委托生命周期；
- 一次性完成、取消、迟到回调和销毁顺序；
- 原生错误到托管错误的稳定映射。

### 10.2 应用与存储测试

- 设备上线、更新、离线、信任和身份变化；
- 所有活动状态转换以及终态不可逆；
- 发送回调与结果事件不会产生重复记录；
- 重试创建新记录并关联旧记录；
- 每设备 500 条和 30 天清理规则；
- 异常退出后的数据库与设置恢复；
- 文件临时名、重名、发布和清理。

### 10.3 ViewModel 与界面测试

- 设备选择、导航和空状态；
- 配对安全码确认与拒绝；
- 发送、接受、拒绝、取消和重试；
- 窗口关闭转托盘、通知跳转和受控退出；
- 浅色、深色、高对比度、双语和键盘导航；
- 960×640 到大窗口及 100%–200% 缩放。

这些测试使用可替换的 SDK 门面和存储接口，不要求真实局域网。

### 10.4 真实集成与验收

使用实际 `unishare.dll` 验证 Windows↔Windows、Windows↔Android 和 Windows↔iOS：

- 发现、离线与重新发现；
- 首次配对、信任保持、忘记和身份变化；
- 文本、图片、文件和剪贴板；
- 接受、拒绝、取消、超时和断网；
- 文件完整性、重名与临时文件清理；
- 窗口隐藏时的接收通知；
- 应用重启后的设备信任和活动摘要。

## 11. 完成标准

Windows 首版满足以下条件时视为完成：

- 安装后可以初始化并持续运行现有 SDK；
- 可信设备和附近设备被清晰区分；
- 用户最多两次操作即可向选中设备发送支持的内容；
- 可信设备的文本与剪贴板自动接收，图片与文件按策略确认；
- 关闭窗口后托盘接收继续工作，显式退出能完整停止；
- 每个活动项都有明确且正确的状态、进度或错误说明；
- 不为历史记录保存内容副本；
- 双语、明暗主题、键盘和屏幕阅读器要求通过；
- 单元、界面状态、原生桥接及真实跨平台验收全部通过。
